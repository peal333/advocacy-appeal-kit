# Customize without AI

You need the extracted toolkit, a desktop browser, public source material, and any images you have permission to publish.

The root `index.html` is your cause website. The root `editor.html` is the visual editor. Keep the whole extracted folder together. The older `app/setup/index.html` entry still works.

## Open and edit

1. Extract the **whole toolkit ZIP** and open `editor.html` in your browser. Keep its folders together. Do not open it from inside a ZIP viewer. No install, terminal, server or online account is required.
2. Start with the instructional template (`Your campaign title`), or choose **Open backup** to load this kit's editable backup ZIP or version-1 campaign JSON. JSON does not contain images; restore the image files with their original filenames through **All fields → Images & permissions**.
3. In **Edit page**, click outlined page text and type directly. The selected item gets a blue outline and pencil label. The right sidebar shows that item's properties. Inline editing uses plain text. Press Escape to leave a text field; use the sidebar for dates, URLs and other structured details.
4. Click **Page settings** for the campaign ID, language, updated date, appearance, optional petition URL and sharing metadata. Desktop preview is a 1,100-pixel viewport; Mobile is 390 pixels. The canvas scales down to fit your editor window.
5. Click **Hero image** or the page's hero illustration to choose one PNG, JPEG or WebP image. Replacement clears the alternative text so you describe the new image. Missing alternative text produces an accessibility warning, but you can still preview and export. Add creator, source and permission information. Old images are retained in the project and can be managed through **All fields**. Images are limited to 5 MiB and 40 megapixels each; do not include confidential metadata or filenames.

## Contacts, messages and supporting content

In the contact sidebar, start with **Name / office** and **Public email**, then choose a **Group** if useful. **More details** opens the optional role, country, provenance, priority and message overrides plus the read-only identifier. Closing it does not discard values; **All fields** still shows every field. Clicking a review issue opens any hidden details before focusing the field.

- **Contacts & groups:** replace the non-real example recipient, or add a recipient and enter their name and public email. Add a role under **More details** if useful. Optional **Country** is below **Role** in the sidebar and All fields, and appears below the role on public contact cards when supplied. Leave it blank when unknown or unnecessary. Never guess an address. Public source URL and verification date are optional, and may be entered independently. Leave them blank if not recorded rather than inventing them. Supplied values must be valid.
- **Manage groups:** add a group separately, then choose it from a contact’s group dropdown. Groups can remain empty and are saved in the project ZIP. Renaming a group updates its member contacts. Deleting a group takes effect immediately, without a confirmation dialog, and preserves all its contacts as **Ungrouped**. Removing a contact also takes effect immediately in both Visual edit and All fields; choose **Save to ZIP** before deleting if you may need to recover it. Groups label the public recipient cards; they do not send messages or apply group-wide templates.
- **Message template:** edit the default subject and body. The supported placeholders are `{{name}}`, `{{personalMessage}}` and `{{recipient}}`. A contact can override either field; leave an override blank to inherit the default. Visitors remain responsible for reviewing and sending messages.
- **Page sections:** add or reorder extra sections, timeline entries, sources and further links. Add sources before selecting them in timeline/event controls. A source in use cannot be removed in the contextual editor until its references are updated. Review actual verification dates and public links.
- **Optional event:** use a sourced date-time with an explicit time zone and an after-event message. Do not invent an exact time for an approximate or unconfirmed event.
- **All fields:** use the original form editor whenever you need the complete field list or full image inventory. Both editors work on the same data and exports.

## Optional page features

Open **Page settings** or **Page sections → Header, sharing & optional sections**; **All fields** has the same section. Use these settings to configure the top header title, sharing controls, header timer, bottom sections and footer. These settings are distinct from the campaign's main title and existing sourced event.

- **Header and sharing:** leave the header title blank to keep the campaign ID. Enable sharing only with the intended public website URL; optional share wording otherwise uses the title/summary. Copy link, WhatsApp, Facebook, X and browser-native sharing where available use that public URL, not your local editor address. Review drafts without posting.
- **Header timer:** choose a label, an optional explicit-timezone date-time, a human-readable date label and after-date text. If only a date is confirmed, leave the date-time empty and use the date label instead; no live countdown is appropriate. Check any existing event separately so two inconsistent deadlines do not appear.
- **Bottom sections:** enable Background and enter its title/body; configure Timeline and Sources titles/visibility using their existing records; add Existing Efforts with titles, descriptions and public URLs. Explicitly configured Timeline appears below the appeal area. Disable a feature to hide it, not to erase its stored data. Remove sensitive or obsolete content from the data itself.
- **Footer:** supply your verified X/Twitter profile URL only if you want a follow link; leave it blank otherwise. Edit the middle text and choose whether to show the campaign's updated date. Do not invent an account or a review date.

Existing projects without these settings retain their legacy event, timeline, sources and footer behavior. Before saving, check both enabled and disabled layouts at both widths, the date-label-only and passed-date states, and long text. Clipboard and native sharing availability depend on the browser; inspect fallbacks in the actual browser rather than assuming a successful source or unit test proves them.

## Review and save

1. Open **Review before export** in the sidebar. Complete fields marked **\*required** (shown in red) and fix errors. Empty required fields show a reddish border immediately, without needing to focus or leave the field; it clears as soon as the value is valid. The edit canvas stays available while a new entry is incomplete, but both ZIP exports remain blocked until validation passes. Warnings still require human review; validation cannot verify truth, consent or permissions. Missing poster alternative text is a warning, and blank contact source/verification fields are allowed. Neither blocks preview or export.
2. Switch to **Visitor preview**. Editor outlines and pencil labels disappear. Review both widths, recipient-specific messages and all links. Both this preview and the finished website show every recipient as a card with their public details. Select a card’s radio control to prepare one recipient’s draft; keyboard users can Tab to the choice and use arrow keys to change it. The selected recipient is shown above the personalization fields. In Edit page, selecting a card opens its contact properties instead of preparing or sending email. Opening an email app does not send a message. Do not send test messages to real recipients.
3. Choose **Save to ZIP** and check that the download finished. This is your main take-away file: it contains the regenerated root website, this toolkit, your current campaign, every listed image, an updated offline bundle and fresh checksums. Extract the downloaded ZIP into a new folder and open its `editor.html` to verify it. Your campaign and images load automatically. Upload this one ZIP to an AI chat for later changes, or continue manually in the extracted editor. You do not need the original toolkit.
4. Choose **Download website ZIP** for a public hosting package from your current valid editor data. It contains root `index.html`, relative styles/scripts and only selected hero/social images, not the editor or unused media. It neither publishes nor marks the editable project saved: use **Save to ZIP** separately and continue from that newest project. **Open backup** accepts data/media backups and supported JSON, not whole project ZIPs. There are no separate editable-backup or JSON download buttons. AI and the [CLI workflow](ai.md) can produce those companion exports. Never publish the complete project, which retains editor/source files and unused media.
5. Complete the [publication review](review-and-recovery.md), then follow the [hosting guide](publish-cloudflare.md) only when you approve publication.

Edits live in memory, not in an automatically saved account. Closing or refreshing can lose unsaved changes. Save and confirm the project download before closing. Save creates a new ZIP download; it cannot overwrite the original ZIP or extracted folder. Continue from the newly extracted copy, not an older folder. There is no application-wide Undo/Redo or Cancel button. Your browser may undo text in the focused field, but that is not reliable recovery for deleting groups, sections or images. To discard unsaved changes, reload/close the editor and accept the browser's leave warning if shown; reopen your last saved project. Keep older saved versions until the new one is verified. Saving requires valid campaign data. Complete or remove incomplete entries before saving; there is no separate incomplete-draft download.

The importer accepts only this kit's unmodified, uncompressed backup ZIPs. Do not unzip and recompress them before import. Total images are limited to 19 MiB, campaign JSON to 1 MiB, and website/editable-backup archives and backup imports to 20 MiB. The full project ZIP has a separate 50 MiB limit because it also carries source files and embedded media for offline startup. Migration from unrelated platforms is not part of this prototype.

See [recovery](review-and-recovery.md) and [verification status](verification.md). Actual browser acceptance testing is still required; automated checks are not visual or browser certification.
